# MaxKB 原生召回本地验证记录

日期：2026-11-10。代码基线：`92c0de8`；工作分支：`codex/knowledge-search-v1`。
环境：本机已有 MaxKB v2.10.7-lts，非测试服、非生产验收。
该环境包含历史 Embedding 适配和启动脚本挂载；下面的结果不能等同于纯官方镜像的验证结果。
挂载位置与部署步骤见 [部署手册](maxkb-deployment-guide.md)。
通过 MetaAgent 的真实 `search()` 客户端调用原生应用 API，使用已有通义 embedding/rerank 配置。

## 资料与评测口径

逐段核对旧审核稿的 16 个已发布段落及线上原文/启用状态，从中选出 13 份适用内容，
复制到独立场景库和操作库。按楼层拆成文档，原文内容保持一致；新增标签与楼层关联问题。
旧知识库、旧应用及业务配置保持原样。

基线仅使用旧目录中启用的两个 `scene_kb`，各以 `blend/top_number=24/similarity=0` 调原生 hit_test，
合并原始分数取前六条。该实验复现旧候选合并方式，**不是整个旧 MetaAgent 的端到端回放**。
单层段落按审核标题确定楼层；大块单独标记混层，不把含目标层的大块计为“纯异楼层”。

## 结果

| 类别 | 用例 | 结果 |
| --- | --- | --- |
| 二楼别名/内容 | 介绍二楼、介绍2楼、二层有什么、2F有哪些房间、二楼有哪些诊室、问诊中心在二楼吗 | 6/6 仅二楼来源 |
| 其他楼层对照 | 介绍一楼、介绍三楼、3F有什么、介绍三层、四楼有哪些评估室、五楼的数据中心介绍 | 6/6 仅目标层来源 |
| 多层比较 | 二楼和三楼有什么区别、二楼三楼分别是什么中心 | 2/2 同时包含二、三楼来源 |
| 未知目标 | 介绍六楼、介绍20楼、介绍这里 | 3/3 为 no_evidence，正文和来源为空 |
| 界面操作 | 底下那个麦克风是干什么的、我想回社交岛怎么弄、设置旁边那个返回按钮是干什么的 | 3/3 限于操作库，均包含对应原文问答 |

共 20/20 通过。验证的是来源范围、正确原文存在、状态和契约，不是最终回答质量评分。

| 单层来源指标 | 旧场景库候选基线 | 新原生工作流 |
| --- | --- | --- |
| 含纯异楼层来源的问题 | 12/12 | 0/12 |
| 纯异楼层 chunk 总数 | 24 | 0 |
| 含多楼层混合大块的问题 | 12/12 | 0/12 |
| 目标层来源命中 | 本次未单独汇总 | 12/12 |

不把基线的 12/12 解读为线上错误率；小规模开发样本没有保留集，且多项配置同时改变，
不能分离分块、标签、关联问题、阈值和重排各自的贡献。新方案没有通过大量拒答降低这组单层题的错误。

20 次新流程的单次耗时：p50 562.5 ms，p95 891 ms，最大 1016 ms。
串行小样本，未做并发压测，不能当作线上 SLA。

额外边界验证：

- 非授权空间返回 `knowledge_access_denied`，客户端按权限错误处理，无证据落库。
- 128 预算无法容纳来源，返回 `no_evidence` 和预算缺口；600 预算返回 `partial`，保守计量 502。
- `help` 域询问二楼仍只返回二楼；`product` 域询问麦克风仍进入操作库并包含正确原文。
- 对本次创建的五楼文档临时移除 published 标签、临时停用，分别得到 `no_evidence`，未兜底到其他层；
  随后恢复标签与启用状态，再次命中五楼。原业务文档未修改。
- 原生工作流导出成功，生成 18,821 字节的 `.mk`（目标环境导入后需重新绑定库和模型）。

## 代码检查

客户端、协议、证据与探测相关测试 79 项通过；原生调用保持一次 POST、无历史、无楼层参数，
验证普通聊天输出/失败包装不能变成证据、错误映射和配置检查。
补充标准文件头检查通过。非 integration 完整回归为 398 通过、15 失败、1 跳过；
15 个失败与基线一致，属于问诊入口、业务会话及历史测试，未新增失败。
PostgreSQL 用例因未配置独立测试库跳过。Ruff、修改代码格式及 `git diff --check` 通过。
生成器输出与提交候选中的工作流 JSON 一致：28 个原生节点、34 条连线，无自定义工具节点。
